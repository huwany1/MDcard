# 分屏实时预览

同一稿件更新时继续显示上一版完整预览，标题旁显示“正在更新预览…”。正文、块索引和源码映射在解析结果提交时一起切换。首次打开、尚无本稿件快照时才显示“正在准备首次预览…”。

## 两个独立条件

`RichUi::displayable` 要求快照属于当前 editable buffer 和打开 generation；它只允许显示。`source_ready` 仍要求实际安装版本等于当前正文 revision，且没有等待提交的小文档源码。

旧快照期间不运行预览的 reading plan、校准、geometry 捕获、阅读记录写入或预览到源码的滚动同步；公式/图表的源码编辑和 Edit 按钮暂时不可用。媒体重试、画布缩放和平移可以继续工作，写回仍经过既有源码哈希校验。保存与恢复草稿的既有版本保护保留。

新文件不能使用前一文件的快照。大文档解析另使用独立 `parser_epoch`；退出 64 KiB 适配器再返回，即使打开 generation 和内部 revision 数值重复，也不能接受上一周期的后台结果。

## 调度和资源

| 路径 | 调度与上限 |
| --- | --- |
| 小于 64 KiB | 120 ms 空闲防抖，300 ms 最长等待；保留一个最新 pending source 和一个显示快照 |
| 不小于 64 KiB | 现有 Rope / Tree-sitter 增量线程、分块转换缓存和视口挂载；一个运行任务、一个排队任务、一个结果槽 |
| 密集输入编辑日志 | 最多 256 个累计 InputEdit，超出后合并为最新 Rope 的重置解析 |
| 后台结果 | 同 parser epoch，版本不晚于当前源码，并严格新于已接收版本；允许展示完成的中间版本 |
| 解析缓存 | 保留既有转换缓存 4,096 项 / 32 MiB、语义页缓存 512 项 / 32 MiB |
| 富媒体结果 | 保留既有 1,024 项 / 64 MiB；队列 4 个请求及 1 个执行请求 |
| 图片 | 64 个最近 URI 的尺寸/等待记录；淘汰时调用 `forget_image` 清除对应 loader / texture 缓存 |
| 诊断 | 预览提交记录最多 2,048 条，媒体完成与滚动决策记录各最多 256 条；普通构建未设置报告路径时不采这些记录 |

连续输入达到最长等待后可以提交一版，不要求先停止输入；停止后提交最后一版。编辑焦点与 TextEdit 状态不随预览更新重建。

## 滚动锚

每次绘制记录顶部附近最多四个内容块的 key、原索引和相对像素位置。提交后寻找仍存在的内容块，保留其位置。它只是像素锚，不授予使用旧源码坐标的权限。

若当前阅读锚尚无可靠 relocation proof，同 buffer / generation 的有效像素锚优先于旧阅读记录的近似回放；保持到当前源码 index 和当前帧 galleys 生成新 geometry，再重新记录当前阅读位置。已有可靠 proof 的恢复继续走原流程。用户滚动或主动导航可以取消保持。

实际排版改变锚之前的高度时，hold 同步加上该补偿。该帧的 galleys 仍来自补偿前位置，因此不会确认阅读 geometry 或释放 hold；等补偿后的 offset 真正绘制，再捕获当前 geometry。这避免把相邻段落误当作稳定锚。

离屏粘贴等编辑使用独立 `source_reveal` 重新挂载源码窗口，不设置预览跳转。源码/预览的高度补偿、阅读恢复和输入光标自动显露产生的 offset 变化留在本栏；只有指针位于该栏的真实滚轮或拖动手势才将滚动传给另一栏。TOC、搜索结果和导航键继续使用明确的导航通道。目录展示及消费跳转时都验证当前文档、源码版本和解析版本，防止旧 heading 的字节坐标越界或跳到另一段。

## 媒体等待与恢复

图片等待和失败只占对应块，使用最近成功尺寸或 160 逻辑像素的初始高度，实际调用 `set_min_height` 保留空间。15 秒未完成显示超时说明和 Retry image；坏格式/错误地址显示具体原因和重试入口。加载完成后按真实尺寸排版，现有视口锚补偿处理高度变化。

公式/图表使用既有独立 worker 和冷启动/渲染超时；失败卡片有“重试渲染”，行内公式可在右键菜单重试。其他正文仍可读、可滚动、可编辑。解析超过五秒或线程已退出时，预览说明原因并提供“重试预览”。

主循环不再固定每 250 ms 唤醒。防抖、目录扫描、保存、恢复、阅读索引/持久化、搜索、导出、媒体以及显式截图/自动退出分别安排自身的唤醒。

## 验证入口

先构建同一候选并隔离设置、恢复和阅读数据，再执行真实 Windows 桌面验证。需要 Python、Pillow、imageio-ffmpeg、psutil；脚本会改变前台窗口与剪贴板，请让其独占测试桌面。

```powershell
python -X utf8 scripts/verify-preview-windows.py --exe App/MDcard.exe --output evidence/preview/local-check --scenario matrix --bytes 16776192
python -X utf8 scripts/summarize-preview.py evidence/preview/local-check
```

性能脚本保存原生动作时间、屏幕采集起止时间、每帧像素哈希、UI 报告、提交阶段计时和录屏。屏幕时延采用“对应编辑完成后的稳定正文像素完全一致”的首次帧，不能用 spinner 像素变化代替。输出请求数、完成数和缺失/截尾数；缺失样本不构成完整 P95 达标。

UI 命令生成、GL 回调完成和桌面捕获观察分别报告。均不能冒充物理显示器面板的呈现时间。录屏按名义 20 fps 编码，实际采集速度可能不同，持续时间应读动作和帧时间戳。

本轮本地证据及未达目标见 [2026-10-27 验收](REALTIME_PREVIEW_ACCEPTANCE_2026-10-27.md)。本机日常入口统一放在被忽略的 `App/MDcard.exe`；它是本地更新，不代表 GitHub Release 已替换。批量比较显式传入 `run-preview-acceptance.py --candidate-exe <exe> --baseline-exe <exe> --measured-baseline-exe <exe> --output <新目录>`；仅测候选时使用 `--candidate-only`，不依赖历史候选散落目录。
