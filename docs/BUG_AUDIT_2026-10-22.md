## 已确认 Bug

### BA-001 / P1：节点草稿防抖期间保存写入旧内容，新建直接丢失草稿

- 发现版本：基线 0.1.1，原版 Windows 程序。
- 触发：编辑公式/图表源码后，在 250ms 自动同步之前点击工具栏保存；同类风险包括导航/语言切换/导出。
- 预期：先把待提交节点草稿同步到权威源码，再保存或执行破坏性命令；同步失败保留草稿并阻止命令。
- 实际：主代理将 `x^2` 改为 `z^3` 后约 122.7ms 点击 Save，700ms 后磁盘仍为旧 `x^2`，界面处于 dirty；另一次修改后约 129.9ms 点击 New，直接得到空白未命名文档，无未保存提示，草稿 `z^3` 丢失。
- 根因：帧开头仅针对 Ctrl+S/N/O/Q 与 native close 强制 flush；工具栏与其他命令入口未经过相同边界，节点窗口更新发生在工具栏之后。
- 修复：新增 `flush_rich_edits(ctx)->bool`，保存/导航/搜索/导出/编码/语言切换/native close 共用提交边界；节点 patch 失败阻止命令，保留文档与草稿，不因失败清除待处理错误。副编辑器保持其原有独立路径。
- 失败后的继续工作：stale 草稿不能自动重定向到新源码。浮动/行内节点错误区提供“放弃待同步的节点编辑…”与二次确认，说明先复制需保留内容；取消不清草稿，明确确认后只清节点待提交状态，不改主/副文档或磁盘。新控件三条文案均有六语言翻译，report 暴露请求/取消/确认按钮。
- 验证：`pending_formula_is_included_in_save_and_navigation_dirty_guard` 修复前失败、修复后通过；另有 stale 草稿不覆盖磁盘、不允许 New、显式放弃后保存当前源码、副文档保持，以及搜索/导出/编码读取最新草稿回归；真实 egui 点击验证二次确认取消/放弃语义。最终 Windows 候选还经实际键鼠验证可复制 `z^3`、取消保留、放弃仅清节点、保存 `$outside$` 原稿、正常退出。
- 状态：已修复并通过主代理最终 Windows/Linux 原生验收。
- 证据：`evidence/bug-audit/master-review/baseline-rich-boundaries/result.json`、`baseline-rich-new/result.json` 及同目录 PNG；`implementation/rich-before.log`、`rich-after.log`；重放 `scripts/verify-bug-audit-rich-boundaries.ps1 -Action Save|New -RequireFixed -Exe <新程序>`。
- 失败恢复证据：`evidence/bug-audit/master-review/stale-draft/result.json` 与 2 张截图，最终 Windows SHA256 `c368e398d34acc12be0691dd0fd81eea4bffa8b66034ce31c62b4afc2bb2f384`；确认 Cancel 保留可复制的 `z^3`、放弃只清节点、当前 `$outside$` 原稿可保存并正常退出。

### BA-002 / P1：搜索忽略目录大小写不一致，可能修改历史目录

- 发现版本：`b34f2f2`；类型：已确认功能/数据保护缺陷。
- 触发：工作区存在 `TARGET`、`.GIT`、`Node_Modules`、`.MDCARD-HISTORY` 等目录，包含受支持文本。
- 预期：与文件树和文档约定一致，不区分 ASCII 大小写排除构建/依赖/历史目录；提交边界拒绝历史路径。
- 实际：索引收录 5 个文件而非唯一可见文件；提交边界对 `.mdcard-history` 也仅作大小写敏感比较。在 Windows 大小写不敏感文件系统中会暴露真实历史目录。
- 根因：`Index::refresh` 使用 `contains`，`commit` 使用精确字符串比较。
- 修复：两处改为 `eq_ignore_ascii_case`，回归同时验证索引与直接提交历史路径拒绝。
- 验证：`skipped_directories_and_history_are_case_insensitive` 修复前失败，修复后通过；search 8/8。
- 状态：已修复并通过主代理验收。证据：`evidence/bug-audit/implementation/skipped-before.log`、`search-after.log`；最终 Windows 94 项核心测试及 `master-review/search-limit/result.json` 验证四个实际忽略目录均未收录。

### BA-003 / P2：单文件超过搜索结果上限时未标记结果不完整

- 发现版本：`b34f2f2`；类型：已确认结果呈现缺陷。
- 触发：单文件出现 10001 个匹配。
- 预期：只显示 10000 条并标记 limited；恰好 10000 条时仍为完整。
- 实际：两种情况均 `count=10000, limited=false`，用户不能发现遗漏。
- 根因：单文件 Matcher 先静默截断，Index 未得到超限信号。
- 修复：只在搜索路径保留 1 条 lookahead 匹配，让全局结果组正确标记；查找窗口显示六语言“结果不完整 · 已达到匹配上限”，report 含 `results_limited`；替换仍对超限预览直接拒绝，禁止静默部分替换。
- 验证：`one_file_result_overflow_is_marked_incomplete_but_exact_limit_is_complete` 修复前失败、修复后通过；`truncated_results_have_a_visible_warning_in_the_search_window` 使用真实 10001 命中并检查 egui 绘制文本含提示，证据 `implementation/results-warning.log`。
- 状态：已修复并通过主代理验收。证据：`evidence/bug-audit/implementation/limit-before.log`、`search-after.log`；`master-review/search-limit/result.json` 与截图证明实际 10001 命中只显示 10000 条，并明确显示 Partial results 警告，已人工看图。

### BA-004 / P1：副文档中打开“当前文档”替换却修改主文档

- 发现版本：基线 0.1.1；类型：已确认错误目标编辑。
- 触发：主窗格 `main.md` 内容 `cat-main`，副窗格 `second.md` 内容 `cat-secondary`；聚焦副编辑器，Ctrl+H，查找 `cat` 替换为 `dog` 并应用。
- 预期：查询、Diff、应用、撤销重做与保存均针对副文档；主文档内存与磁盘保持不变。
- 实际：主代理原版 Windows GUI 记录查询分组为 `main.md`，应用后主文档变为 `dog-main`，副文档仍为 `cat-secondary`。
- 根因：`search_overlays()` 固定主文档在前，`Index::documents(single)` 取第一个；单文档应用也固定调用主编辑器的 `apply_rich_source`。
- 修复：打开搜索时捕获活动窗格；单文档 query/preview 使用目标窗格，应用检查目标身份与内容后写入该窗格，复用原生 TextEdit 单次撤销事务并恢复副编辑器焦点；跨文件事务/回滚依旧检查全部已打开文档，避免遗漏 dirty 保护。
- 验证：`current_document_replace_tracks_the_active_secondary_pane_and_its_history` 修复前因目标 main/second 路径不一致失败；修复后检查主文档 clean、磁盘两份不改、副文档 dirty，以及一次 undo/redo 通过。
- 状态：已修复并通过主代理最终 Windows/Linux 原生验收；`master-review/release-active-pane/result.json` 与 `master-review/linux/result.json` 均验证查找/替换/单次撤销重做/保存针对副文档，主文档不变。
- 证据：`evidence/bug-audit/master-review/baseline-active-pane/result.json` 及两张 PNG；`implementation/active-pane-before.log`、`active-pane-after.log`；重放 `scripts/verify-bug-audit-active-pane.ps1 -RequireFixed -Exe <新程序>`。

### BA-006 / P2：单个巨大目录可绕过搜索扫描预算

- 发现版本：`b34f2f2`；类型：已确认后台资源边界缺陷。
- 触发：一个目录内包含超过文件预算的受支持文本，或大量无关条目；扫描线程在该目录内持续遍历。
- 预期：整个刷新遵守 100000 文件/500000 条目/15 秒预算，在条目与内容读取之间检查取消/截止；触及预算明确标记索引不完整。
- 实际：文件数和时长仅在外层“下一个目录”之前检查，一个目录的内层遍历不检查取消/预算，因此可收录超过 100000 文件，长时间不响应停止。
- 直接复现：将同一生产扫描实现的预算作为私有参数注入，目录内 5 文件、文件预算 2，修复前 `status.files <= 2` 失败；不是另写一份模拟扫描器。还验证条目预算 2 的路径。
- 修复：生产 `refresh` 固定传入 500000/100000/15秒；内层逐条检查条目/文件/时长/取消，内容读取阶段每文件前检查相同 deadline。单次阻塞 I/O 仍无法强制中断，不宣称严格 15秒墙钟上限。
- 验证：`single_directory_search_scan_obeys_file_and_entry_budgets` 修复前失败；修复后 search 9/9 通过。证据 `evidence/bug-audit/implementation/scan-budget-before.log`、`scan-budget-after.log`。
- 状态：已修复并通过主代理最终复核；最终 Linux 96 项、Windows 94 项与独立 search 52 项均包含同一生产扫描实现的预算回归。
