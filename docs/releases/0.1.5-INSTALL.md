# MDcard 0.1.5 本地安装与迁移

本次仅交付本地安装产物，未公开发布或改写历史版本。版本 0.1.5 包含 `D:\MDcard` 的冻结主线源码，以及完整离线公式、图表、九种导出运行时。无需安装 Node、Java、Chromium、Pandoc 或开发工具。

## Windows x64

1. 核对 `SHA256SUMS.txt` 后运行 `MDcard-0.1.5-windows-x64-setup.exe`。
2. 默认按当前用户安装到 `%LOCALAPPDATA%\Programs\MDcard`，无需管理员权限。确认安装目录后，选择可选入口，点击“安装并启动”。界面直接采用系统语言，完整许可文本保留在安装目录的 `LICENSES.txt` / `licenses` 中。
3. 安装结束自动启动，也可从开始菜单打开。桌面快捷方式与 Markdown“打开方式”注册均可选，默认不选。已有默认 Markdown 应用不被强制替换；需要时在 Windows 的“打开方式”中选择 MDcard。
4. `Ctrl+O` 打开，`Ctrl+N` 新建，`Ctrl+S` 保存，`Ctrl+Shift+S` 另存为。`Ctrl+E` 切换编辑、分屏和阅读，`Ctrl+F` 搜索，`Ctrl+Alt+E` 导出。

当前支持声明沿用项目的 Windows 11 x64；Windows 10 未验收。安装器尚未购买代码签名证书，Windows 可能提示未知发布者；以本地清单和 SHA256 核实来源，不宣称具有 SmartScreen 信誉。

升级和卸载前先保存并退出所有 MDcard 窗口。安装器发现 MDcard 正在运行时会要求关闭，不会自动杀死编辑器。重复运行同一安装器可以修复应用文件；升级使用相同应用身份。通过 Windows“已安装的应用”卸载。

应用设置位于 `%APPDATA%\MDcard`，阅读状态和崩溃恢复位于 `%LOCALAPPDATA%\MDcard`。卸载只处理安装器拥有的程序文件、入口和关联注册，不默认删除这些用户目录或文档。安装中断后先保留文档与上述目录，再重新运行完整安装器修复；不保证任意断电时刻都具有事务回滚。

## Debian 12 amd64

从包含安装包的目录执行：

```sh
sha256sum -c SHA256SUMS.txt
sudo apt install ./mdcard_0.1.5_amd64.deb
```

从应用菜单或 `mdcard` 启动。程序安装到 `/opt/mdcard`，命令入口 `/usr/bin/mdcard`，图标和桌面入口由标准目录提供。运行时无需 root。

`apt` 根据包的 `Depends` 安装桌面图形、字体、音频及 portal 系统库；这些系统包可能需要联网下载。应用自身所有 Node/Java/Chromium/Pandoc/字体已在安装包内，不会在安装或首次使用时另行下载。可在目标机执行 `apt --simulate install ./mdcard_0.1.5_amd64.deb` 查看依赖方案；实际额外下载量取决于该机器已安装的软件包。

本轮 Linux 桌面验收环境为 Debian 12 x86_64 / glibc 2.36、X11、Openbox、Xvfb 与软件 Mesa，内核为 Docker Desktop 的 WSL2 内核。没有把该结果扩展成 Ubuntu、Wayland、其他桌面或显卡驱动的验收声明。原生文件对话框需要可工作的桌面 portal。Linux 导出需要支持 pidfd 的内核及相应权限。

升级时再次 `sudo apt install ./新版本.deb`，卸载使用 `sudo apt remove mdcard`。安装/升级和移除前的简短维护脚本检查 `/proc` 中正在使用的 MDcard，发现运行中或无法安全确认时会报错，请先保存退出后重试。包不会杀死应用、删除用户目录或下载运行时。异常中断后保留用户数据，使用 `sudo dpkg --configure -a`，必要时 `sudo apt --fix-broken install`，再安装完整包。

设置默认在 `${XDG_CONFIG_HOME:-$HOME/.config}/MDcard`，阅读状态和恢复默认在 `${XDG_STATE_HOME:-$HOME/.local/state}/MDcard`。`apt remove` 和 `apt purge` 都不会主动遍历用户 home 删除这些文件。

## 从旧便携版迁移

1. 在旧版中保存所有文档，关闭全部旧窗口，备份文档和上述用户目录。不要把“恢复记录”当作文档备份的替代品。
2. 保留原便携目录，独立安装新版。通过新版的开始菜单/应用菜单打开原来的文档，无需把文档搬入程序目录。
3. 默认使用相同用户的既有设置和恢复目录。原文件自动保存保留原选择；缺失设置时自动保存关闭、独立崩溃恢复开启。阅读状态 v3 使用独立文件，避免旧写入器覆盖新格式。
4. 如果旧启动脚本设置过 `MDCARD_SETTINGS_PATH`、`MDCARD_READING_STATE_PATH` 或 `MDCARD_RECOVERY_DIR`，先从脚本确认实际路径，再在两端都退出时备份并复制到标准目录；不要猜测或覆盖仍有新编辑的状态。
5. 验证原文档、设置和需要的恢复副本后，再自行决定是否删除旧便携目录。安装器不会替换 `D:\MDcard\App`，也不会删除旧目录中的用户文件。

## 开发者重建

在干净源码目录准备 Git、Python 3.11+、Node 24.21.0/npm、Docker Desktop Linux engine，运行 `scripts/build-release.ps1`。构建依赖、官方运行时/JDK/Inno Setup 的固定输入见 `packaging/build-inputs.json`、Rust toolchain 和 npm/Cargo 锁文件。脚本不公开发布产物，也不安装产品。

编译与打包成功之后仍须执行实际安装验收；三次测量、运行时调用、默认用户目录和数据保留证据见本次验收报告。不同系统工具链或 apt 仓库更新可能影响二进制字节；源码、运行时和工具版本均需记录，未承诺跨日期位级重现。
