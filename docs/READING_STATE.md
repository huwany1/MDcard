# 独立阅读状态基础合同

本文说明当前文件身份、独立视图、持久化和安全降级的基础约束。文字/源码行的精确恢复、大幅修改后的重定位及并发清除语义见[精度合同](READING_PRECISION.md)。合同不是本次平台 GUI 已通过的证明。

- 默认是最后停留位置。最远浏览位置和已读标志独立；滚到底部不会自动已读。若显示比例，其语义为“当前位置”。
- DocumentId 独立于打开代次。保存文件按规范化绝对路径关联；未命名文档拥有独立运行时 ID，本文不承诺草稿内容跨重启恢复。外部移动不能自动识别原身份；应用内部重命名在锁内迁移路径与稳定身份。
- 同一路径同时出现在主副窗格时仍共享文件 DocumentId；每份可编辑正文另有不持久化的 BufferId，源码索引与后台元数据按二者组合隔离。缓存最多保留两个活动 buffer，不用每帧全文哈希识别正文；后台保存返回的新 buffer 也能继续记录位置。
- 每文档分别记录 main/source、main/preview、secondary/source 的横纵偏移、内容源锚点、上下文、标题路径、块内比例及视口位置，另存光标/选区、最后活动视图、内容指纹、布局签名、更新时间。
- 内容和布局不变时直接恢复横纵偏移，验收逻辑像素容差为每轴不超过 2 px（报告实际误差）。布局变化按源码块锚点恢复；块内比例仅是近似，不代表同一个字或同一行。
- 内容变化优先上下文和标题；重复上下文须由前文/标题唯一判别，否则退回唯一附近标题或文档比例。锚点删除、空文档和缩短均夹取到有效边界。文字/源码行与大幅修改后的精确定位遵循[精度合同](READING_PRECISION.md)，须区分文字命中、块级降级与实际视口误差。
- 旧文档状态在打开前主动排队落盘，只有目标打开成功后提交身份。搜索/目录及用户主动滚动优先于历史恢复。恢复任务同时校验 DocumentId 和打开代次。
- 阅读文件位于 Windows LocalAppData/MDcard/reading-state-v3.json，Linux XDG_STATE_HOME 或 ~/.local/state/MDcard；不写 Markdown、原稿恢复或替换历史。测试用 MDCARD_READING_STATE_PATH 隔离。
- 滚动只改内存；初始 500 ms 防抖、持续滚动 3 s 周期、切换和关闭主动提交。后台临时文件+同步+原子替换，按文档更新时间合并；Windows LockFileEx / Linux flock 系统锁保护稳定锁文件，进程退出由系统释放。锁忙或失败保留内存并可从设置查看；不能宣称异常退出零丢失。
- 限制 512 条/4 MiB，保护活动窗格记录；提供当前文件与全部清除入口。原稿字节和保存失败保护保持原有 Document 路径。
- MDCARD_READING_REPORT 为纯观测 JSON；诊断写入不属于产品阅读记录写频性能。

支持多实例按文档合并；并发与原子替换故障由根项目和独立回归验证，实际平台运行需单独记录。

当前 schema 3 的并发清除屏障、安全迁移和后台元数据语义见[精度与存储合同](READING_PRECISION.md)。根项目及 tests/reading-acceptance、reading-store-acceptance 保留直接源码回归。
