## 测量合同（实施前冻结）

1. 源码逻辑行、当前排版视觉行和 Unicode 字素簇分别建模。文字级恢复要求对应内容身份正确，并将目标字素簇的实际布局顶部恢复到保存的视口纵向坐标，误差 ≤2 个逻辑 px；同布局偏移两轴各 ≤2 px。
2. 以首个可稳定映射到原稿的可见文字作为观测候选，规则由实现合同明确；顶部非文字/隐藏语法/生成内容必须明确降级。跨宽度后视觉行号不要求一致，实际目标字素簇要求一致。
3. 裁边独立统计。块级、章节级、近似结果不计入文字精确命中；光标/选区精确不代表阅读精确。诊断的 `exact` 标志、旧偏移或候选分数不是正确答案。
4. 独立集固定至少 1000 个可判定对应样本、200 个歧义样本、200 个删除/无对应样本。先冻结生成器、输入、答案及 SHA，再运行算法；完整保留失败/超时。可判定精确命中率 ≥98%，整个独立集观测到的错误精确声明数量必须为 0。该门槛不是任意文档零错误承诺。
5. 大幅编辑量以编辑操作插入+删除的 Unicode scalar 数除旧文本 scalar 数计算；另列移动原内容块数/原块数。测试必须包含 ≥30% 字符编辑及 ≥30% 块移动的样本，不用 UTF-8 字节长度夸大中文编辑比例。
6. 输入路径不向产品注入位置、精确结果或人为等待。Windows 使用原生键鼠/文件对话框，JSON 仅只读观察，源文本独立核对，截图核对真实呈现；自然异步加载后的稳定区间至少 2 s。
7. 主线程捕获+恢复计划+入队预算：同机真实滚动样本 P95 ≤2 ms、单次 ≤8 ms；真实按需文字排版另列，不冒充位置捕获。整 GUI update 的 P95 相对同机同输入基线增量 ≤max(基线 P95 的 20%, 2 ms)。后台取消可见响应 ≤100 ms。索引、后台匹配、排版和磁盘时间分别报告 P50/P95/max/样本数，墙钟不称线程 CPU/显示时延。不得测试后放宽预算。
8. 性能矩阵包含普通、1 MiB、10 MiB、长段落和大量重复内容；不得每帧全文扫描、哈希、挂载或写盘。缓存/状态容量和失效规则单独验证。
9. Windows 必验。若交付 Linux 包则提供当前 Linux GUI/资源证据；X11/Xvfb 不代表 Wayland 或所有桌面。最终包必须与最终源码/二进制/资源清单 SHA 对应，再从包内运行关键用例。

## 测量与取消审计保留项（历史取证，当前结论见R29）
