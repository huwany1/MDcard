# 业务边界审查

基线 `0cf20e3`。本次不是“业务文件零改动”：`main.rs`、`export_ui.rs`、`search_ui.rs`、`recovery.rs` 是UI与业务混合文件，其中仅修改能隔离的展示部分。完整补丁见 `evidence/ui-ux/2026-10-28/presentation-only.diff`；机器核查见同目录 `business-boundary-audit.json`，由 `scripts/ui-ux-boundary-audit.py` 可复核。

| 修改文件 | 展示用途 | 保留的执行边界 |
| --- | --- | --- |
| `theme.rs` | 配色、字号层级、圆角、窗口内边距、平面菜单、等分导航、身份行、工具行、主按钮、模态布局测量、开关绘制 | 开关仍仅在原有clicked时反转；导航仍只选择原navigation值；焦点/恢复/数据处理不移入样式层 |
| `main.rs` | 工具栏/侧栏/内容/状态布局，身份与保护状态容器，设置/编码/保存确认/错误/重命名展示；测试窗口初始位置与不激活配置 | 原文档请求、保存、提交、打开、快捷键、设置持久化、导出目标绑定保持原实现 |
| `search_ui.rs` | 第二窗保存/关闭的控件命中高度、同一行保护状态 | 第二窗读写、撤销、搜索、替换、关闭保护和结果导航均未修改 |
| `export_ui.rs` | 源文档身份、格式/主题/纸张分组、字段宽度、分隔线、窗口尺寸、底部主按钮 | 原same_source条件、format/pipeline分支、快照、原生选择器、后台任务、取消、发布及清理保持不变 |
| `recovery.rs` | 原生16px标题与窗口约束、预览Frame、恢复主按钮、稍后处理对齐 | 原恢复/删除条件、追踪时机、操作调用、独立草稿/磁盘语义保持不变；没有搬移恢复/删除业务块 |
| `locales/ui.json` | 为已有导出格式选择增加“格式”标签，六种语言各一条 | 无键迁移、设置或数据格式变化 |

核查结果：40个未修改的受保护源码文件保持阶段一SHA256；58个关键业务函数的规范化源码逐字一致，包括打开/保存/请求/快捷键/持久化、导出start/poll/report、搜索与替换处理、恢复写入/发现/认领/删除/操作和原保护状态方法；`renderer/` 的Git差异为空。`document.rs`、`autosave.rs`、`preferences.rs`、`encoding.rs`、`large_document.rs`、`source_layout.rs`、`reading_*`、解析/搜索内核和vendor均不改。

逐hunk人工审查补充了哈希不能覆盖的混合函数：UI闭包增加布局容器，原事件条件和命令仍在原位置；主窗口update仅改变面板尺寸/边距与保护状态展示调用；编辑/预览仅更改头部工具行，正文入口、坐标、选区与解析代码不变。为通过仓库fmt检查，格式变化局限于已修改展示闭包；`git diff -w`可排除纯缩进，未重构业务实现。

`MDCARD_WINDOW_POSITION`仅在验收启动器提供合法坐标时设置Viewport初始位置并禁用初始激活；未提供时保持正常启动语义。它不写持久化设置，且不改变文档、快捷键或渲染器选择。

真实GUI核验补充：编辑/保存精确字节、撤销/重做、查找定位、切换文件、第二窗、原生打开、PDF导出、键盘导航和模态焦点恢复。完整根测试结果为291通过、0失败、6项原本显式忽略；忽略项不算通过。未重复执行所有独立acceptance工程、全部九种导出格式或网站部署；本轮业务内核和renderer没有差异。

验收发现的原有问题：关闭第二窗后`last_secondary`仍可保留true，直接从菜单导出会绑定已关闭窗的身份而禁用。未修改的 `open_export` 实现及原始 `baseline-linux` 已分别验证；`validation-native/baseline-export-focus/02-original-disabled-export.png` 记录复现，03记录点击主区后恢复可用。最终核心流程明确先点主编辑区再导出，不能将原组合边界伪报为通过。
