## 环境与输入隔离

- 主验收环境：Debian 12 / X11 / 专属容器 `mdcard-ui-native` / 专属 Xvfb `:141` / Mesa 软件 OpenGL，96 DPI、100%。常规窗口 1240×820，窄窗 680×480。每张 PNG 的同名 JSON 保存主题、字号、真实 UI 状态、控件矩形、源码修订、截图 UTC 时间与程序 SHA256。
- Windows 补充实机：Windows 11，左屏 144 DPI / 150%，1240×820 逻辑、1860×1230 物理。`baseline/02-read-left-valid.png` 已直接打开检查。Windows 首次启动在右屏的历史截图不作为最终对应比较。
- 用户要求右屏工作不受干扰后，停止 Windows 全局输入、鼠标移动、抢焦点和剪贴板操作。所有后续交互在专属 Xvfb 进行。设置、恢复副本、阅读位置、测试稿件全部隔离。真实用户稿件与日用 App 没有被覆盖。
- 早期 Windows 定向消息实验存在黑图/点击未生效，保存在 `rejected-windows/`，不计有效截图。最终对应比较使用同平台、同尺寸、同样本的 Linux 原生图；Windows 另作原生视觉核对。

## 具体问题与设计方向

1. **内容顶部被辅助信息挤占。** 文件名下的全宽蓝线、单独占32像素以上的“自动保存关闭”“崩溃恢复开启”、编辑区工具行连续堆叠；正文到窗口约270像素才出现。将身份、保护状态、编辑工具区分为紧凑且有层级的三层，保护状态同行展示，错误仍允许自然展开。
2. **两条顶部工具区缺少组织。** 交通灯、工作区、品牌、无文字图标、带边框菜单、搜索与模式选择缺乏明确强弱。标题层使用较深的染色表面，工具层使用中性表面；文件快捷操作轻分组，菜单采用平面行，模式选择维持独立右端区域。
3. **侧栏密度和对齐不稳定。** 文件夹工具紧跟短名字，导航采用不同宽度胶囊；虚拟列表28像素行再加全局8像素间距导致文件项稀疏，树与计数缺少节奏。使用固定尺寸导航分段、右对齐工具、真实28像素行、清晰选中标记。
4. **文件身份过于弱，活动线过于强。** 文件名与面板小字比例近似，路径只能悬停，全宽强调线抢占视觉重心。使用15像素加粗标题、11像素可截断路径、短活动标记和中性分隔线；修改状态仍来自真实dirty值。
5. **编辑与预览标题行比例不统一。** “结构操作”小按钮、折行控件、11像素标题并排高度差异明显。采用统一28/32像素工具高度，面板文字11像素，正文保持现有用户字号和实际排版行为。
6. **设置是狭长的顺序清单。** 390像素弹窗承载所有选项，开关、说明与分隔线缺少成组关系；底部路径长且难辨。扩大到520像素可用宽度，使用 section 标题、横向行和右对齐开关；持久化代码与选项语义不改。
7. **窄窗设置真实越界。** 从大窗口收窄时，上缘被裁切、首项不在视口。设计限制弹窗在当前内容区，滚动体与固定操作区分开，并验证尺寸切换及重新打开。
8. **浮窗像默认调试面板。** 默认大字标题、蓝色标题条、极窄内边距、功能按钮与输入混排。统一窗口标题/内边距/中性边界与明确底部操作区；搜索、导出、结构和恢复沿用真实功能。
9. **保存确认的三按钮权重接近。** 保留明确主按钮、中性取消和可辨认的丢弃按钮，按钮高度统一，长文件名正文自动换行。不要把恢复更新误写成原文件已保存。
10. **柔和感需要保持可读。** 辅助文字在所有表面上仍须满足已有4.5:1回归约束；禁用项以较低强调度和工具提示表达，不使用近白文字。焦点使用清晰描边，选中与悬停区分。

## 未捕获的状态与边界

持续数百毫秒的索引/解析加载、保存失败的OS权限错误、富节点校验失败、替换冲突/回滚失败等未在本阶段稳定复现，没有使用推测图冒充截图。替换历史为空是实际状态。公式/图表源码窗口尚未稳定打开，后续若影响其专用布局会补拍；共享视觉规则仍会由真实原生应用验证。Windows原生文件选择器由系统绘制，保留系统外观，不将HTML原型当作它的实机图。跨系统字体栅格差异单独说明。

本次修改范围限于展示层、布局和必要纯UI状态。读写、保存、恢复、解析渲染、搜索替换、导出管线、持久化设置、数据格式和快捷键行为均不在改动范围内。
